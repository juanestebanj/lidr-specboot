# Self-manufacturing Specboot through AI-assisted SDD

## Why
The fork has engineering guidance but no repository self-specification, generated distribution contract, or CI proving that its own toolkit can be reproduced. Canonical guidance and the copied npm template drift. The user requests that Specboot manufacture and improve itself through AI-assisted SDD.

## What Changes
Adopt the uploaded bootstrap as explicitly proposed source-maintenance scaffolding, retain its historical evidence, and add deterministic template generation, provenance manifest, fail-closed self-checks, package-boundary verification, Linux CI and a source-maintenance guide. Import the bounded installer exit-status correction with its evidence. Keep human acceptance separate from implementing agents.

## Capabilities
- self-manufacturing: canonical sources -> generated customer template -> verifiable npm payload -> temporary installed project.
- Existing installation and source-maintenance contracts remain applicable; bootstrap acceptance is not automatically granted.

## Impact
Canonical docs/ and ai-specs/ feed packages/specboot/template/. New scripts and tests are source-only. The npm payload gains a deterministic template manifest. No source-only specifications, test suites, CI or execution reports enter customer projects.

## Non-goals
No autonomous model training, background task, automatic acceptance, merge, publication, deployment, privileged permission change, database, API or browser application is introduced.
