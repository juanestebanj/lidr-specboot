# Specboot customer onboarding

Specboot provides reusable engineering guidance and agent workflows for OpenSpec. This is the dedicated customer onboarding artifact, independent of the customer root README.

1. Install and initialize a trusted compatible OpenSpec version in your project if needed. Do not run unreviewed remote installation scripts.
2. Review the shared `docs/base-standards.md`, backend/frontend/documentation standards, and the canonical `ai-specs/agents/` and `ai-specs/skills/` directories.
3. Customize the example technical context (API, data model, development guide and agents) to your actual project; do not assume the example stack applies.
4. Configure your project's OpenSpec context to reference the applicable standards and agents. Keep your own requirements and verification rules authoritative.
5. Verify root and agent-specific symlinks and correct onboarding content. Preserve existing customer files; resolve conflicts deliberately.
6. Use the relevant skills to enrich requirements, specify changes, implement, review independently and verify evidence. Obtain authorized acceptance before archival or delivery.

See the upstream Specboot project for release-specific setup guidance. Source-repository self-specifications are not customer product specifications. Optional external integrations are separate, explicitly authorized setup activities.
